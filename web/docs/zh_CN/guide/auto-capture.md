# 使用 QD 在线录制签到

在「我的任务 → AI 编写签到模板」打开 AI 签到工作台，再选择「使用 QD 在线录制」。也可以访问 `/ai-workbench/?mode=browser`。此入口在站点能正常使用 QD 浏览器时适用。

## 启用在线录制

管理员需设置 `AI_WORKBENCH_BROWSER=true`，并使用支持 Chromium 的 QD 构建、单进程 Web 服务和独立的 `COOKIE_SECRET` 与 `AES_KEY`。已有数据库部署应继续使用原有密钥，替换示例密钥前需先完成加密数据迁移。项目的 Docker Compose 示例支持设置这些变量。源码部署可运行 `playwright install chromium` 安装，或用 `PLAYWRIGHT_CHROMIUM_PATH` 指定已安装的 Chromium。[模型设置](./ai-sign-template.md#配置模型)

## 在工作台录制

1. 打开签到网站，在 QD 浏览器中亲自登录，按站点提示完成验证，再进入签到页面。账号和验证信息请在站点表单中输入。
2. 可以选择「已登录，自动识别签到」。工作台无法确定下一步时，按提示继续操作并结束录制。也可以从「手动录制」开始，完成签到后选择「结束录制并分析」。
3. 在网页中查看签到结果，再检查录制脚本并选择「试跑脚本」。确认后按需要「保存模板」「保存并签到」或「保存并定时」。定时执行使用服务器时间。
4. 已有浏览器任务需要重新验证时，从任务列表或日志进入「重新验证」，完成站点验证后选择「验证完成，恢复任务」。

站点无法在 QD 浏览器中完成正常登录时，用自己的桌面浏览器登录并手动签到，导出脱敏 HAR 后回到同一工作台分析。已有 HAR 模板也可以在模板编辑器手动维护。[从 HAR 编写签到模板](./ai-sign-template.md)

## 五、Cookie 获取方式

已有 HAR 模板可能需要用户提供自己账号的 Cookie。可在已登录的桌面浏览器通过开发者工具查看，也可使用 QD 的 `/get_cookies/page` 登录获取页面或 [QD get-cookies 扩展](https://github.com/qd-today/get-cookies)。Cookie 是账号凭据，仅填写到自己受信任的 QD 任务中。在线录制使用工作台内的站点登录流程。
