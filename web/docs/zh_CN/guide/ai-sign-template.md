# 用 AI 编写签到模板

从「我的任务」选择「AI 编写签到模板」，打开 `/ai-workbench/`。可以导入桌面浏览器录制的 HAR，也可以从同一工作台进入 [QD 在线录制](./auto-capture.md)。

## 配置模型

管理员在 QD 服务环境中设置以下变量。使用项目的 Docker Compose 示例时，可以设置在项目目录的 `.env`；配置生效后，在工作台检查页面显示的模型名。

| 环境变量 | 用途 |
| --- | --- |
| `AI_BASE_URL` | OpenAI 兼容 Chat Completions 服务的基础地址，通常以 `/v1` 结尾 |
| `AI_MODEL` | 服务接受的模型名 |
| `AI_API_KEY` | 该服务的密钥 |
| `AI_ALLOW_NO_KEY` | 仅在可信且无需密钥的自建服务上设为 `true` |

页面显示模型名仅表示本地已配置。选择「分析记录」可验证 QD 能否调用服务。

## 从 HAR 起草

1. 在桌面 Chrome 或 Edge 登录站点。打开开发者工具的「网络」面板，清空登录阶段的记录，手动签到一次。导出脱敏 HAR，并检查请求及响应是否仍含账号、会话或其他敏感值。可参考 [HAR 抓包教程](./har-capture.md)。
2. 在工作台填写站点网址，上传 HAR 并选择「分析记录」。工作台从同源记录中整理请求和已观察到的成功信号，模型接收经处理的摘要。
3. 查看草稿，选择「编辑和试跑」。检查请求、成功和失败条件、变量提取及后续引用。工作台为常见同源流程起草，跨站步骤、自定义分支和模型未识别的变量需要在编辑器补齐。
4. 填写试跑参数并选择「试跑所选步骤」。试跑会向站点发送真实请求，手动签到后再试跑可能返回「已签到」。检查每步日志和站点回执，确认业务结果后保存模板。
5. 在「我的任务」选择新模板创建任务，单独填写该任务的参数。试跑参数只用于本次编辑。

## 查看站点回执

在签到步骤勾选「把签到回执写入任务历史」。站点响应提供明确的签到结果时，QD 可以显示「签到成功」「已签到」等结果，以及站点返回的积分等可识别字段。日志里出现「没有可确认的签到回执」时，检查是否选中了实际签到请求，以及站点响应和成功条件能否共同证明业务成功。HTTP 200 只表示网站响应了请求。
